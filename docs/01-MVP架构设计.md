# 架构设计（最终版）

> 这份文档回答三个问题：**谁在控制流程**、**哪些部分交给模型**、**边界划在哪**。
> 读完之后你应该能对着一张白纸讲清整个系统的骨架。

---

## 0. 三个关键决定（决定了后面所有实现）

### 决定 1：用真实 HTTP，不用 `test_client`

| | 进程内调用（Flask `test_client`） | **真实 HTTP（requests）** |
|---|---|---|
| 能测什么 | ❌ 只能测 Python/Flask | ✅ Python、Java、任何能说 HTTP 的服务 |
| 前提 | 无需起服务 | **被测服务必须先跑起来** |
| 代价 | 快 | 网络开销 + 环境依赖（要用探活兜住） |

**为什么必须这样**：要"同一个工具测 Flask 和 Spring"，就不能依赖某个框架的测试钩子。
**"它测的不是 Python 也不是 Java，它测的是 HTTP"** —— 这句话是整个项目的地基。

### 决定 2：被测对象是**配置**，不是代码

```
selfheal/configs/
├── rag-backend.json    Python/Flask，8000
├── java-cms.json       Java/Spring MVC，8080
├── cms-portal.json     JSP+Tomcat，8081
└── demo-buggy.json     故意带 Bug 的示例服务，8090
```

工具不认识"RAG"或"CMS"，只认识契约。**加一个被测项目 = 加一个 JSON，工具代码零改动。**

### 决定 3：控制流写死在代码里，模型只被"点名"干三件事

```
✅ 真实实现：代码决定顺序（十步），模型只负责 ①写用例 ②打分 ③规则判不了时给建议
❌ 没这么做：让模型自己决定调哪个工具（不可复现、不可审计、不可单测）
```

## 1. 统一架构

```
   需求文档 + 外部规范                  接口契约
   「为什么该这样」                    「接口长什么样、期待什么」
   requirements_docs/ + corpus_external/     configs/*.json
        │ 分块 → SQLite 索引 → hybrid 检索      │
        └──────────────┬────────────────────────┘
                       ▼
        ┌──────────────────────────────────────┐
        │  有界自愈循环（≤2 轮）                  │
        │  探 → 读 → 写 → 校验 → 评 → 快照        │
        │     → 跑 → 分 → 定 → 报                │
        └──────────────┬───────────────────────┘
                       ▼
        ┌──────────────┴───────────────┐
        ▼                              ▼
  reports/REPORT-*.md            .snapshots/（可回滚）
  （通过率/归因/缺陷清单）          evals/generated/（生成用例）
                       ▼
              web/ + server.py（只读报告台 + 一键运行）
```

**两份输入的分工（面试会问）**：

| 输入 | 回答什么问题 | 存在哪 |
|---|---|---|
| **需求文档 / 外部规范** | **该测什么**：业务规则、边界、异常要求、组织规范 | `requirements_docs/<项目>/` + `corpus_external/` |
| **接口契约** | **怎么调、期待什么**：路径、方法、参数、状态码、字段值、鉴权方式 | `configs/<项目>.json` |

> 只有契约 → 只能测"接口通不通"；
> 加上需求 → 才能测"业务对不对"。
> **契约是判定对错的依据，需求是"该测什么"的来源。两者冲突时按"契约与实现不一致 → 挂起交人"处理。**

## 2. 契约长什么样（字段清单）

最小可用版（5 个字段）：

```json
{
  "name": "my-app",
  "base_url": "http://127.0.0.1:9000",
  "health": { "id": "items" },
  "endpoints": [
    { "id": "items", "method": "GET", "path": "/api/items",
      "expect_status": 200, "expect_fields": ["code", "data"],
      "notes": "商品列表，data 必须是数组" }
  ]
}
```

真实项目需要的全部字段（都已在 `java-cms.json` / `cms.json` 里用过）：

| 字段 | 作用 | 为什么需要 |
|---|---|---|
| `id / method / path` | 接口标识与地址 | 用例只通过 `api("id")` 调用，**URL 只有一个来源** |
| `expect_status` | 期望 HTTP 状态码 | 基本契约 |
| `expect_fields` | 响应顶层必含字段 | 结构契约 |
| `expect_json` | **响应体字段的期望值（支持点路径）** | 只断言"字段存在"测不出"值不对"；`{"data.total": 798}` |
| `params` | 查询参数 | 分页（`pageNum/pageSize`） |
| `body` | 请求体 | 写操作必需（**没有它就必然 400/500**） |
| `notes` | 业务含义 | 进提示词，且用于契约体检 |
| `no_auth` | 该接口故意不带登录态 | 验证"未登录必须被拒绝"的鉴权边界 |
| `auth`（顶层） | 登录态：`endpoint/token_path/header/prefix` | token 由工具层自动获取注入，**模型不接触凭证** |
| `requirements_dir` | 该项目自己的需求文档目录 | 不填会检索到"别人的需求" |
| `external_docs` | 外部规范语料目录 | 让生成用例带上组织级约束 |

## 3. 模块划分（16 个，单向依赖）

| 层 | 模块 | 职责 | 关键点 |
|---|---|---|---|
| 编排 | `loop.py` | 十步主循环 + 决策 | 控制流全在这里 |
| 编排 | `server.py` | 报告台（stdlib HTTP） | 只读视图 + 一键运行，**不是平台** |
| 能力 | `generator.py` | 写用例 + 四道静态校验 | 模型只写函数体 |
| 能力 | `critic.py` | rubric 5 维打分 | 只展示，不进控制流 |
| 能力 | `runner.py` | 跑 pytest + 解析 junitxml | 结构化结果，不解析终端文本 |
| 能力 | `triage.py` | 失败分 6 类 | 纯正则，可复现 |
| 能力 | `advisor.py` | 规则判不了时的兜底归因 | 无动作权限 |
| 能力 | `report.py` | Markdown 报告 | 归因而非复述数字 |
| 接口 | `targets.py` | 读契约 + 探活 | 契约唯一来源 |
| 接口 | `http.py` | 发请求 + 自动注入登录态 | 网络错误不抛异常 |
| 接口 | `bootstrap.py` | AI 读源码起草契约 + 契约体检 | 模型起草、代码验形状、人签字 |
| 知识 | `kb.py` | 需求+规范知识库 | 分块 / 检索 / 配额 |
| 知识 | `vectordb.py` | SQLite 向量索引 + BM25 + RRF | 持久化、可评测 |
| 周边 | `snapshot.py` | 快照 / 回滚 | sha256 清单 |
| 周边 | `retrieval/` | chunking/embedding/store/retriever | 可替换（换真 embedding） |
| 基础设施 | `llm_client.py` / `env.py` | 模型调用 / 配置加载 | 重试、空正文兜底、代理绕过 |

**规则：箭头只能向下，不能向上。** 换任何一层，其它层不用改。

## 4. 自愈循环（闭环，可背）

```
探 → 读 → 写 → 校验 → 评 → 快照 → 跑 → 分 → 定 → 报
```

细节与图见 `docs/02-工具调用Loop.md`。

**四个闸门**：探活（服务没起就停手）· 静态校验（毫秒级拦错）· 失败分流（哪些不许修）· 模型权限（只能给建议）。

---

## 5. 分流规则（6 类 → 6 动作）

| 类别 | 判据 | 动作 |
|---|---|---|
| ① 服务不可达 | `ConnectionError` / 探活失败 | **STOP**：什么都不改 |
| ② 系统 Bug（HTTP 5xx） | `HTTP 5xx` / `assert 5xx ==` | **REPORT_DEFECT**：出缺陷清单 |
| ②' 业务码 5xx | `响应体 code=5xx`（后端异常被兜底） | **REPORT_DEFECT**：先核对参数/契约 |
| ③ 契约与实现不一致 | `响应字段值与契约不符` / `响应缺字段` | **HOLD**：挂起，交人确认 |
| ④ 生成代码问题 | `AttributeError` / `SyntaxError` / `NameError` | **REGENERATE**：重写这批 |
| ⑤ 断言 / 脚本问题 | `AssertionError` / `KeyError` / `TypeError` | **FIX**：允许改（≤2 轮） |

**安全边界（面试必答）**：
> 如果模型见到失败就改测试，它会把"接口真坏了"改成"测试通过了"——**缺陷被掩盖，比漏测危险得多**。
> 所以自愈的第一条规则不是"怎么修"，而是"**哪些不许修**"。

## 6. RAG 在这个工具里的位置（已落地）

| 位置 | 用途 | 状态 |
|---|---|---|
| **需求 + 外部规范知识库** | 检索"该测什么"，注入生成提示词 | ✅ 已接入生成链路（SQLite 索引 + hybrid + 配额） |
| **检索评测** | recall@3 / MRR，判断方案好坏 | ✅ `docs/07-检索评测.md`（改述型 87.5% / MRR 0.792） |
| 失败记忆（错→根因→修法） | 检索"这个错以前怎么修的" | ⬜ v2 候选 |

**不做**：接口契约检索（直接读 JSON 更准）、Agent 编排（流程确定）。

## 7. 演进记录（v1 → 最终版）

| 阶段 | 变化 | 触发原因 |
|---|---|---|
| v1 | 只能测自己的 Flask 后端（`test_client`） | —— |
| v2 | 真实 HTTP + 契约 JSON | 要测 Java CMS |
| v3 | 加 runner/triage/snapshot/loop/report | 闭环 |
| v4 | 加 `advisor`（AI 兜底归因）+ `HOLD` 动作 | 发现"200 但数据不符"会被误判成断言问题 |
| v5 | 加 `bootstrap`（AI 起草契约）+ 契约体检 + 报告台 | 手写契约是最后一块重复劳动 |
| v6 | 加 `vectordb` + 外部规范语料 + 接入生成链路 + 评测 | RAG 要有数字才敢讲 |
| v7 | 修 token 预算兜底、PRD 分节、契约瘦身认知 | 真机跑出来的坑 |

## 8. 刻意不做（避免变成"平台"）

任务调度 · 多用户 · 权限体系 · 历史趋势库 · 分布式执行 · **自动修改系统 Bug**（红线）· 自建 LLM 网关

> 判据：**每加一个"平台能力"，边界就模糊一分。** 这个项目的价值在"把一件事做透"，不在"什么都有"。

---

## 9. 已知边界（面试主动讲）

1. 自愈是**整批重写**，不是行级修复
2. **通过用例不沉淀**（没有回归集）→ 单次通过率不代表质量（详见 `docs/08`）
3. embedding 是哈希向量，**没有语义能力**（评测已量化）
4. 写操作要人补 body；登录只支持 Bearer Token（Session+验证码还不支持）
5. 没有 CI 里的真机回归（离线测试 220 项进 CI，真机验证靠本地）
