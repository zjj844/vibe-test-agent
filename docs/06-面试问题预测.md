# 面试可能问的问题（按概率排）

> 用途：面试前 30 分钟过一遍。**不要背整段答案**，每题只想清楚"我要说哪一句"。
> 详细答案在 `docs/03-理解检查题库.md`（为什么这么设计）和 `docs/05-技术栈与名词详解.md`（这个词是什么意思）。
> 📖 **每题的完整口语版回答**见 `06-面试问题预测-完整版.md`（学习期用）；本篇是速查版（面试前用）。

## 零、面试官的四种动机（先想清楚他在验证什么）

| 他在验证 | 会怎么问 | 你要给的东西 |
|---|---|---|
| **是不是你做的** | "这个契约文件你写的？""跑一次给我看看" | 具体的坑、具体的命令、具体的失败 |
| **理解有多深** | "为什么是 2 轮不是 5 轮？" | 一条能说出口的判断依据 |
| **有没有边界意识** | "那如果……呢？"（追问边缘情况） | 承认边界 + 说明为什么这样划 |
| **能不能带** | "你大三，零基础？""这些你多久学会的？" | 诚实 + 方法论（不是"我很努力"） |

**核心策略：所有答案都落到"我怎么判断的"，而不是"我做了什么"。**

## 一、项目主线（几乎 100% 会问）

1. **简单介绍一下你这个项目。**
   → 60 秒版：问题（AI 写的测试不可信、失败说不清是谁的问题）→ 做法（契约驱动 + 十步流水线 + 六类分流）→ 结果（两个语言的项目跑通、127 条自测）。

2. **它到底解决什么问题？**
   → 三件事：不知道测什么（读需求）／失败不会归类（六类分流）／重复犯同一个错（有界自愈 + 快照）。

3. **为什么要做这个？不做行不行？**
   → 直接跑 pytest 也行 —— 但那只是"执行"，没有"归因"。工具的价值在归因和分工。

4. **现在能测什么、不能测什么？**
   → 能：有 HTTP 接口 + 能写契约的项目（Python/Java 都行）。不能：UI 自动化、性能压测、系统 Bug 自动修。

5. **给我看一次运行。**
   → `python demo/buggy_service.py` + `python -m selfheal.loop --target demo-buggy --n 3`，30 秒出缺陷清单。**这是最有力的回答，一定先在家练熟。**

## 二、设计取舍（最容易被追着问，也是最能加分的地方）

6. **自愈为什么最多 2 轮？**
   → 收益递减 + 成本翻倍 + **逼它它就会作弊**（把断言改宽是唯一稳过的动作）+ 最坏耗时可估算。

7. **模型会不会把断言改弱蒙混过关？**
   → 三层防线：分类决定动作（系统 Bug 不给"改测试"这个选项）／反馈只喂可修类／轮数上限 2。**外加 HOLD：数据不符时直接挂起交人。**

8. **系统返回 500，你为什么不改测试让它变绿？**
   → 能改的只有"我看错"（断言/脚本），改不了"它确实坏了"。改断言 = 把缺陷固化成"预期行为"，比漏测更糟。

9. **"HTTP 200 但数据是错的"你怎么处理？**
   → 单列「契约与实现不一致」，动作 HOLD：不改、不重写，交人确认。因为可能是服务错、契约错、用例错，三者只有人能分清。

10. **为什么不直接让模型自己决定调哪个工具（tool calling / Agent）？**
    → 不可复现、不可审计、不可单测。测试要的是可信，不是看起来智能。控制流全在 `loop.py`。

11. **失败了之后，你怎么知道是被测服务的错还是自己代码的错？**
    → 六类规则 + 有序匹配（严重→轻），判不了的才问模型，且模型只给建议。

12. **快照和 git 有什么区别？**
    → git 管人写的代码；快照管程序运行期生成的产物（`evals/generated/`、`.snapshots/`，本就不进 git），带 sha256 可验证回滚。

## 三、AI / LLM 技术（70% 会问，因为投的是 AI 岗）

13. **你用了什么模型？为什么用它？**
    → DeepSeek；生成用 flash（省钱、13 秒/次），评分低温度（要可复现）。

14. **为什么不用 LangChain / CrewAI / LangGraph？**
    → 三条判据一条没满足（流程固定、无多角色、失败代价高）。框架解决"流程不确定"，我的流程是确定的。

15. **为什么不用向量数据库（Chroma 等）？**
    → 语料仅十余块，放内存够用；引入即运维成本；接口是干净的可替换点（`RequirementKB`），要换只改一个类。

16. **RAG 在你项目里干什么？**
    → 只干一件事：把"该测什么"从需求文档里捞出来喂给生成。**注意区分**：RAG 技术 vs 另一个 RAG 仓库（后者是被测对象）。

17. **模型幻觉你怎么防？**
    → 模板固定 import/URL/鉴权注入 + 4 道静态校验（接口 id 白名单、返回对象成员白名单）→ 它编不出契约里没有的接口。

18. **prompt 你怎么写的？**
    → system 里写死纪律（只输出测试函数、禁硬编码 URL、禁 skip、禁吞异常），user 里给该项目的具体任务；失败摘要单独回喂，不塞 system。

19. **评分（rubric）为什么不让模型自己定标准？**
    → 标准必须人定，否则它给自己宽松标准，分数就没意义。模型只按 1/3/5 锚点打分。

20. **两次采样取中位数，为什么不是平均？**
    → 抗离群值；两个样本时中位数偏保守。

## 四、测试基本功（60% 会问，尤其 JD2 有"流程化测试"）

21. **单元测试 / 集成测试 / E2E 的区别？你的项目里各在哪？**
    → 127 条离线测试是单元级（用替身）；三次真机跑是 E2E。

22. **怎么保证测试本身是对的？**
    → 先有人写的基线测试（3 条标准答案）当尺子；静态检查；最后才是 AI 生成。

23. **junitxml 是什么？为什么不用终端输出？**
    → 结构化机读报告；解析文本等于拿正则赌措辞（我因此得到过假绿）。

24. **测试要能在无人环境跑，你做到了吗？**
    → 做到了：模型和服务全部用替身，CI 在 py3.10/3.13 上跑 127 条。

25. **你会不会写自动化测试？写过多少？**
    → 127 条自测 + 生成的用例若干；如实说"自测为主，业务项目经验少"。

## 五、工程与协作（50%）

26. **为什么分成这么多模块？一个文件写完不行吗？**
    → 每个模块只做一件事，模块间单向依赖，各自可测；出问题能定位到模块。

27. **你的测试跑在哪？CI 怎么配的？**
    → GitHub Actions，矩阵 py3.10/3.13，三步：编译检查 → 契约自检 → 离线测试。

28. **前端为什么用 Vue，还零构建？**
    → 报告台是"查看器"不是平台；零构建的判据：打开界面要先 npm install，它就从工具变成了项目。

29. **代码怎么管理版本？有没有分支策略？**
    → 一人开发走 main，每个模块一次提交；如实说没有 code review 流程。

30. **如果两个人同时改这个项目会有什么问题？**
    → 如实说：快照/产物目录会冲突、报告台单例运行；没有并发设计（这是刻意的边界）。

## 六、你的背景（几乎必问，别躲）

31. **你大三，怎么会做这个？**
    → 从"AI 能写代码但写出来的东西不可信"这个具体问题出发，一步步拆出来的。

32. **代码都是 AI 写的吗？**
    → **诚实+判断**：代码是我和 AI 一起写的，但每个设计决策（2 轮、HOLD、不用 Agent）我要求自己能讲清并写进文档。能力上有短板，方法上是有意识的。

33. **你零基础，凭什么觉得能做这个岗位？**
    → 三周从零交付两个可运行项目 + 127 条测试 + 完整文档；实习岗看的是上手速度和方法论。

34. **你最大的不足是什么？**
    → 没有团队协作经验、没做过大型业务系统、性能/并发没碰过。**配一句**：所以我想进团队做真实的工程。

35. **这些技术你学了多久？哪些是硬啃的、哪些是看文档就会的？**
    → 如实分配；提到"不懂的名词我建了一份名词表（72 个）"，这本身就是方法。

## 七、JD2 特有方向（.NET / Power Platform / 医药行业）

36. **我们这边有用 .NET，你接触过吗？**
    → 没有。但接口测试的角度，.NET 服务和 Java 服务对我是一样的 —— 我只认 HTTP 契约（这句话有实物支撑：我已经测过 Flask 和 Spring）。

37. **医药行业的项目要注意什么？**
    → 如实说了解有限，但能说出方向：可追溯、审计日志、变更留痕、数据完整性 —— 而这正好对应我项目里"每轮变更前快照 + 报告可审计"的做法。

38. **Power Platform / 低代码你了解吗？**
    → 没实际用过，如实说；愿意学，且我做过"把流程拆成可检查步骤"的工作，迁移成本不高。

## 八、五个陷阱问题（答错的代价很大）

| 问题 | 错误答法 | 正确答法 |
|---|---|---|
| "这东西能自动修 Bug 吗？" | "能，它会自己修复" | "不修系统 Bug —— 这是刻意的。它只修测试自己写错的部分" |
| "这是测试平台吧？" | "对，是个小平台" | "是工具/报告台，没有调度、账号、多租户，我也不打算做" |
| "你测出真 Bug 了吗？" | 编一个故事 | 讲示例服务的两种坏法 + 如实说还没有"人手没发现"的样本 |
| "用了 RAG + 向量库吗？" | "用了向量库" | "检索用了，但没上向量库，原因是语料规模" |
| "CI 全绿吗？" | "全绿"（没验证过） | "配置了 CI，第一次结果要 push 后看"（绿了才是绿的） |

## 九、面试前 10 分钟的最后自检

能不能不看稿，说出下面这些？

- [ ] **60 秒**讲完项目（问题 → 做法 → 结果）
- [ ] 十步流水线：`探 → 读 → 写 → 校验 → 评 → 快照 → 跑 → 分 → 定 → 报`
- [ ] 六个数字：4 道静态校验 / 6 类失败 / ≤2 轮 / 3 个调用点 / 127 测试 / 2+1 个被测对象
- [ ] 三句必背（见 `05-技术栈与名词详解.md` 第八节）
- [ ] 一次现场演示命令（demo-buggy，30 秒）

**做不到 60 秒讲完 = 前三题就会乱。** 先练这一条。
