## 一、HTTP 与接口

### 1. HTTP
**通俗**：浏览器/程序之间说话的规矩。
**正式**：应用层无状态请求-响应协议，客户端发请求，服务端返回响应。
**本项目**：整个工具的核心假设 —— 「只要对方能用 HTTP 说话，就能被它测」。见 `selfheal/http.py`。

### 2. 请求 / 响应
**通俗**：你问一句，它答一句。
**正式**：Request（方法+URL+头+体）→ Response（状态码+头+体）。
**本项目**：`HttpResult` 就是一份响应的"结构化快照"。

### 3. 请求方法（GET / POST / PUT / DELETE）
**通俗**：GET = 我要看；POST = 我要新建；PUT = 我要改；DELETE = 我要删。
**正式**：HTTP 语义动词，用于表达对资源的操作意图。
**本项目**：契约里每个接口都要写 `method`，如 `"method": "POST"`。

### 4. 状态码（200 / 400 / 401 / 403 / 404 / 500）
**通俗**：服务端的"脸色"。
**正式**：三位数字表达结果类别 —— 2xx 成功、3xx 重定向、4xx 你（调用方）错了、5xx 它（服务端）错了。
**本项目**：分流模块最要紧的判据。**5xx = 系统缺陷**，绝不允许通过改测试绕过。

| 码 | 含义 | 谁的问题 |
|---|---|---|
| 200 | 成功 | —— |
| 400 | 参数不对 | 调用方 |
| 401 | 没登录/令牌失效 | 调用方（缺凭证） |
| 403 | 登录了但没权限 | 调用方（权限不足） |
| 404 | 资源不存在 | 看契约怎么写 |
| 500 | 服务端崩了 | **服务端** |

### 5. 请求头（Header）与 `Authorization: Bearer <token>`
**通俗**：信封上的备注栏。
**正式**：键值对元数据；`Authorization: Bearer <token>` 是携带访问令牌的行业惯例。
**本项目**：Java CMS 靠它鉴权；令牌由工具层自动注入（`http._headers_for`），模型不接触。见契约 `"auth"` 段。

### 6. 查询参数（Query Parameter）
**通俗**：网址 `?` 后面那串。
**正式**：URL 的 `?key=value&key2=value2` 部分，常用分页、过滤。
**本项目**：契约字段 `params`，如 `{"pageNum": 1, "pageSize": 10}`。

### 7. 请求体（Body）与 JSON
**通俗**：信封里装的那张纸。
**正式**：请求携带的结构化数据；JSON 是 `{键: 值}` 的文本表示，前后端通用。
**本项目**：契约字段 `body`；`HttpResult.json_body` 是解析后的字典。

### 8. URL / 端口 / 路径
**通俗**：`http://127.0.0.1:8000/api/ask` = 协议 + 机器 + 端口 + 路径。
**正式**：端口是机器上区分服务的编号（8000、8080、3306…）；路径是服务内部的资源位置。
**本项目**：`base_url` 存机器+端口，`path` 存路径 —— 换项目只改这两处。

### 9. 契约（Contract）
**通俗**：一份"说好应该怎样"的清单，双方都按它办事。
**正式**：接口的约定集合（方法/路径/期望状态码/期望字段/期望值）。
**本项目**：`selfheal/configs/*.json` 就是契约。**加一个被测项目 = 加一个 JSON**。

### 10. 端点 / 接口（Endpoint）
**通俗**：一个具体的"可调用入口"。
**正式**：一个 method + path 组合。
**本项目**：`Endpoint` 数据类（`targets.py`），`frozen=True` 不可变。

### 11. CORS
**通俗**：浏览器的一条安全限制：不同域名之间默认不让你随便调接口。
**正式**：跨域资源共享，靠服务端返回 `Access-Control-Allow-*` 头放行。
**本项目**：Java CMS 里配了 CORS 并放行 OPTIONS 预检；写测试时不需要额外处理。

### 12. 探活（Health Probe）
**通俗**：先敲一下门，看有没有人在。
**正式**：发一个最小请求确认服务可用，通常用健康检查接口。
**本项目**：`targets.probe()`。服务不可达 → **立即停手**，不生成、不执行。

## 二、测试基本功

### 13. 测试用例（Test Case）
**通俗**：一条"给了什么输入、应该得到什么结果"的检查。
**正式**：包含前置条件、输入、预期结果的可执行检查单元。
**本项目**：一条 `def test_xxx():` 函数就是一个用例。

### 14. 断言（Assert）
**通俗**：写下"我认为它必须是这个"，不对就报错。
**正式**：用语言级断言表达预期，失败即抛 `AssertionError`。
**本项目**：`assert r.status == endpoint.expect_status`；模板里还封装了 `check_contract()` 做三连检查。

### 15. pytest
**通俗**：Python 里最常用的测试运行器。
**正式**：Python 测试框架，靠"文件名 `test_*.py` + 函数名 `test_*`"自动发现用例。
**本项目**：所有被测用例都跑在 pytest 上；127 条自测也是。

### 16. fixture（夹具）
**通俗**：用例的"公共准备工作"。
**正式**：pytest 的依赖注入机制，在用例前后提供/清理资源。
**本项目**：`tests/conftest.py` 里的 `ws_tmp` 提供一个工作区内的临时目录。

### 17. 单元测试 / 集成测试 / 端到端测试
**通俗**：测一个零件 / 测几个零件组合 / 测整条链路。
**正式**：按被测范围从小到大；单元测试最快最稳，端到端最接近真实但最慢最脆。
**本项目**：127 条基本都是**单元测试**（用替身）；三次真机运行是**端到端**。

### 18. 替身 / Mock / Stub
**通俗**：拿假货顶替真货，专供测试。
**正式**：用可控的假实现替代真实依赖（模型、网络、数据库）。
**本项目**：测试里把 `llm_client.chat_for`、`run_tests` 全换成假的 → **离线可跑、不花一分钱**。

### 19. 跳过（skip）与失败（fail）的区别
**通俗**：fail = "测了，不对"；skip = "没法测，先不算"。
**正式**：pytest 两种非通过状态；`skip` 不计入失败率。
**本项目**：被测服务没起时基线测试 **skip 而不是 fail** —— 环境问题不该污染统计。

### 20. junitxml
**通俗**：pytest 输出的"机读版成绩单"。
**正式**：JUnit 风格的 XML 报告格式，CI 系统通用。
**本项目**：`runner.py` 用 `pytest --junitxml` 拿结构化结果。**解析 XML 而不是解析终端文字**。

### 21. traceback（堆栈）
**通俗**：报错时那一长串"从哪一行调用到哪一行"。
**正式**：异常传播路径的完整记录。
**本项目**：分流模块的输入；AI 兜底归因也读它。

### 22. 回归测试（Regression Test）
**通俗**：改完代码，回头确认"原来的功能没被改坏"。
**正式**：为已修复问题/既有功能固化的测试集，防止退化。
**本项目**：目前**还没做**（每轮产物会归档，不累积）—— 这是已知缺口。

### 23. 假绿（False Green）
**通俗**：明明坏了，报告却是绿的。
**正式**：测试结果与真实状态不符的假通过。
**本项目**：踩过 —— 把 XML 标签 `<failure>` 误当状态名 `failed` 去匹配，导致所有失败解析成通过。

### 24. 通过率
**通俗**：`通过数 ÷ 总数`。
**正式**：通常只统计 pass/fail，skip 不计入分母。
**本项目**：报告「概览」表格里的核心数字；但**归因比通过率更重要**。

## 三、Python 工程

### 25. Python 3.10+ 的类型标注（`str | None`、`list[str]`）
**通俗**：给变量/参数注明"它应该是什么类型"，写给人看也给工具看。
**正式**：PEP 484 类型提示；运行时**不强制**，但能防一大类低级错误。
**本项目**：`def probe(target: Target, retries: int = 1) -> ProbeResult:` 全是类型标注。

### 26. `from __future__ import annotations`
**通俗**：让旧版 Python 也能写新式类型标注。
**正式**：把注解延迟成字符串求值。
**本项目**：所有模块首行都有。

### 27. `@dataclass` 与 `frozen=True`
**通俗**：自动生成"构造函数 / 打印 / 比较"的小类。
**正式**：数据类装饰器；`frozen=True` 表示创建后不可修改（不可变对象）。
**本项目**：`Endpoint`、`HttpResult`、`Verdict` 都是 —— **可变的配置是 bug 的温床**。

### 28. 正则表达式（Regex）
**通俗**：用来"描述文本形状"的迷你语言，如"任何 5 开头的三位数字"。
**正式**：字符序列匹配模式，支持字符类、量词、分组、替换。
**本项目**：`triage.py` 的规则表（`r"HTTP 5\d\d"`）和 `generator.py` 的代码块提取。

### 29. 异常处理（`try / except / finally`）
**通俗**：可能会出事的地方先铺个垫子。
**正式**：捕获异常走降级路径；`finally` 无论是否异常都执行。
**本项目**：网络失败不抛异常而是变成 `HttpResult.error`；快照/评分失败只降级不中断。

### 30. 上下文管理器（`with`）
**通俗**：进入时打开、离开时自动关，不会忘。
**正式**：实现 `__enter__/__exit__` 的对象，保证资源释放。
**本项目**：`with VectorStore() as store:`、`path.open(...) as f`。

### 31. `pathlib.Path`
**通俗**：路径也能当对象用，不用字符串拼接。
**正式**：面向对象的路径操作（`/` 拼接、`glob`、`read_text`）。
**本项目**：所有文件读写都是 `Path`；换平台也不会错分隔符。

### 32. 子进程（`subprocess`）
**通俗**：从 Python 里启动另一个程序，比如 pytest。
**正式**：创建子进程执行外部命令，可设超时、重定向输出。
**本项目**：`runner.run_tests()` 用 `subprocess.run([sys.executable, "-m", "pytest", ...])`。

### 33. 线程（`threading.Thread`）
**通俗**：让两件事同时进行。
**正式**：同一进程内的并发执行单元（受 GIL 限制，适合 I/O 等待型任务）。
**本项目**：报告台的"点一下跑一次"在后台线程跑，页面才不卡死。

### 34. `http.server`（标准库）
**通俗**：Python 自带的一个迷你 Web 服务器，能收请求、返内容。
**正式**：标准库 HTTP 服务器实现（`BaseHTTPRequestHandler` / `ThreadingHTTPServer`）。
**本项目**：`server.py` 就是它 —— **不引 Flask/FastAPI，因为目的是"打开就能看"**。

### 35. CLI（命令行工具）
**通俗**：在终端里敲命令用的程序。
**正式**：通过命令行参数控制行为的程序接口。
**本项目**：`python -m selfheal.loop --target java-cms --n 3`。

### 36. 环境变量 与 `.env`
**通俗**：不写进代码的配置（尤其是密码）。
**正式**：进程级键值配置；`.env` 是本地存放它的约定文件。
**本项目**：`DEEPSEEK_API_KEY` 只从环境读，`.env` 在 `.gitignore` 里，绝不提交。

### 37. 依赖（requirements.txt）
**通俗**：这个项目需要别人先装好哪些库。
**正式**：依赖声明文件，`pip install -r requirements.txt` 一次装齐。
**本项目**：只有 `requests` 和 `pytest` 两行 —— 故意保持极简。

### 38. 虚拟环境（venv / conda）
**通俗**：每个项目一个独立"工具箱"，互不污染。
**正式**：隔离的 Python 解释器 + 包目录。
**本项目**：开发时用的 Anaconda 的 3.13 环境；CI 里用 `setup-python` 建干净环境。

## 四、大模型（LLM）相关

### 39. LLM（大语言模型）
**通俗**：读过海量文本、能接着往下写的模型。
**正式**：基于 Transformer 的大规模自回归语言模型。
**本项目**：DeepSeek（`deepseek-flash` / `deepseek-v4-pro`）。

### 40. 提示词（Prompt）与消息角色（system / user / assistant）
**通俗**：你对模型说的话。
**正式**：`system` 定规矩、`user` 提要求、`assistant` 是模型之前的回答。
**本项目**：`generator.SYSTEM_PROMPT` 里写死"只输出测试函数、禁止硬编码 URL"等纪律。

### 41. temperature
**通俗**："发挥度"。0 = 最稳，不瞎编。
**正式**：采样温度，越低输出越确定。
**本项目**：生成与评分都用低温度 —— **要的是可复现，不是创意**。

### 42. max_tokens
**通俗**：最多说多少个"词块"，防止它滔滔不绝。
**正式**：单次响应的 token 上限。
**本项目**：生成给 8000（要写完整代码），评分给 3000，归因给 1200。

### 43. token
**通俗**：模型眼里的"半个词"，计费和长度都按它算。
**正式**：分词器输出的最小单位。
**本项目**：也是成本单位 —— 一次生成本机实测约 13 秒。

### 44. 推理模型（reasoning model）
**通俗**：先"在心里打草稿"再回答的模型。
**正式**：输出前生成推理轨迹（`reasoning_content`）的模型。
**本项目**：`deepseek-flash` 与 `deepseek-v4-pro` 都是；生成为省钱用 flash。

### 45. 幻觉（Hallucination）
**通俗**：一本正经地胡说八道。
**正式**：模型生成看似合理但事实错误的内容。
**本项目**：实测它会写 `r.json()`（不存在的成员）—— 所以才需要**静态校验**兜住。

### 46. RAG（Retrieval-Augmented Generation，检索增强生成）
**通俗**：先去资料里翻，再让模型照着答，别凭记忆。
**正式**：检索相关文档片段注入上下文，再生成答案。
**本项目**：只用于**"读需求"**一步 —— 从需求文档里捞出"该测什么"塞进提示词（`kb.py`）。

### 47. 向量 / Embedding
**通俗**：把文本变成一串数字，好算"谁和谁像"。
**正式**：把离散符号映射到连续向量空间，用余弦相似度等度量语义相近。
**本项目**：用**自实现的哈希向量**（`HashingEmbedder`，2048 维），没有外部模型 —— 语料只有十余块，不值得上真模型。

### 48. 分块（Chunking）与重叠（Overlap）
**通俗**：长文档太长，切成小段才能检索；相邻段留一点重复，免得话被切断。
**正式**：按长度或结构切分文本，重叠区用于保持上下文连续。
**本项目**：按 H2/H3 标题切节，节内再按 300 字 / 60 重叠切块，块 id 形如 `REQ-001-鉴权与登录#s02#c00`。

### 49. Top-K 检索
**通俗**：只取最像的前 K 条。
**正式**：按相似度排序取前 K 个结果。
**本项目**：`top_k=3` —— 多了会挤占提示词，少了会漏。

### 50. Rubric（评分量表）
**通俗**：打分用的标准表，写清 1 分、3 分、5 分各长什么样。
**正式**：带锚点描述的评分维度集合。
**本项目**：`critic.RUBRIC` 五维（可执行性/断言明确性/需求覆盖/独立性/可维护性），**人写的标准，模型只打分**。

### 51. 采样与中位数
**通俗**：同一个东西问两遍，取中间那个分。
**正式**：多次独立采样后取统计量，抑制单次抖动。
**本项目**：`samples=2` 取中位数（2 个样本时取较小者，偏保守）。

### 52. Agent / 工具调用（Tool Calling）
**通俗**：让模型自己决定"接下来调哪个函数"。
**正式**：模型输出结构化调用指令，由外部执行并回填结果，循环直到完成。
**本项目**：**刻意不用**。控制流写死在 `loop.py` 里 —— 可复现、可审计、可单测。

### 53. LangChain
**通俗**：一个把"模型 + 提示词 + 工具 + 记忆"串起来的**框架**。
**正式**：LLM 应用开发框架，提供 Chain / Agent / Tool / Memory / Retriever 等抽象与集成。
**本项目**：**没有使用**（见第 7 节）。

### 54. CrewAI / LangGraph（多 Agent 编排）
**通俗**：让好几个"角色"分工协作的框架。
**正式**：多 Agent 协作编排，支持角色定义、任务分派、状态图。
**本项目**：**没有使用**，理由同上。

## 五、架构与工程实践

### 55. 契约驱动（Contract-Driven）
**通俗**：先把"说好应该怎样"写下来，代码都围着它转。
**正式**：以接口契约为中心驱动测试生成、执行与校验的开发方式。
**本项目**：**一句话卖点** ——「加一个被测项目 = 加一个 JSON」。

### 56. 编排（Orchestration）
**通俗**：谁先谁后、出错了走哪条路，由总控决定。
**正式**：把多个模块按固定顺序/条件组合成流程的代码。
**本项目**：`loop.py` 的十阶段流水线；**控制流全在代码里，模型只负责"写"和"评"**。

### 57. 自愈（Self-healing）
**通俗**：测挂了，能自己修一修再试。
**正式**：根据失败反馈自动修正测试代码并重跑的机制。
**本项目**：**有界自愈**，≤2 轮，且只修"测试自己写错了"那几类。

### 58. 有界（Bounded）
**通俗**：给它装个刹车，一定会停。
**正式**：对重试次数、耗时、动作范围施加硬上限。
**本项目**：轮数 ≤2、pytest 超时 900s、单次 HTTP 超时、静态检查不过就不执行。

### 59. 幂等（Idempotent）—— 顺带一个没直接用到的词
**通俗**：做一次和做十次，结果一样。
**正式**：重复执行不改变结果的特性。
**本项目**：属于测接口时要注意的性质（例如"提交订单"重复提交会重复下单），**本工具目前不自动检测幂等**，属于可扩展点。

### 60. 快照与回滚（Snapshot / Rollback）
**通俗**：改之前先拍照，改坏了能退回去。
**正式**：对文件状态做带校验的备份，可原样恢复。
**本项目**：`snapshot.py`，每轮变更前拍照，`restore()` 可回滚。

### 61. SHA-256 与清单（manifest）
**通俗**：给文件算一个"指纹"，改一个字节指纹就变。
**正式**：密码学哈希；清单记录每个文件的路径、哈希、大小。
**本项目**：快照目录里的 `manifest.json`，保证"回滚真的回到了那一刻"。

### 62. 白名单 / 黑名单
**通俗**：只允许列出来的（白）／只禁止列出来的（黑）。
**正式**：allowlist / denylist 策略。
**本项目**：`_HTTPRESULT_MEMBERS` 白名单限制模型能访问的字段；报告名白名单防目录穿越。

### 63. 目录穿越（Path Traversal）
**通俗**：用 `../` 跳出允许访问的目录，去读别人的文件。
**正式**：通过相对路径绕过路径校验的攻击方式。
**本项目**：`server.load_report()` 只接受 `Path(name).name == name` 且以 `.md` 结尾。

### 64. 故障域（Fault Domain）
**通俗**：出问题时先判断"哪一块坏了"，再决定修哪里。
**正式**：按责任边界划分的故障归属范围。
**本项目**：六类分流就是在划故障域 —— 服务端 / 契约 / 用例 / 环境，各归各管。

### 65. 降级（Degrade）
**通俗**：高级功能挂了，退回低配模式继续干活。
**正式**：非核心依赖失败时提供受限但可用的能力。
**本项目**：评分失败、快照失败、AI 归因失败都只记一条备注，不让主流程崩。

### 66. Git / commit / branch / remote / push
**通俗**：代码的"存档 + 多人协作"系统。
**正式**：分布式版本控制；commit 是一次快照，branch 是并行线，push 是上传到远端。
**本项目**：20 余次提交，每个模块一次；`origin` 指向 GitHub。

### 67. CI（持续集成）/ GitHub Actions
**通俗**：一 push，机器自动在干净环境里跑一遍检查。
**正式**：Continuous Integration；Actions 是 GitHub 提供的免费 CI 服务，按 workflow YAML 执行。
**本项目**：`.github/workflows/ci.yml`，py3.10 / 3.13 双版本跑 127 条离线测试。

### 68. 徽章（Badge）
**通俗**：README 上那个红/绿小图标。
**正式**：由 CI 状态动态生成的图片。
**本项目**：`ci.yml` 的 badge；**绿了才有意义，红了要撤掉**。

### 69. LICENSE / MIT
**通俗**：说清楚"别人能不能用你的代码"。
**正式**：开源许可证；MIT 最宽松，允许商用与修改，只需保留版权声明。
**本项目**：根目录 `LICENSE`（MIT）。

### 70. npm / Vue / 构建（Build）/ vendor / 零构建
**通俗**：前端也要装依赖、打包；"零构建"就是跳过这一步。
**正式**：npm 是 JS 包管理器；build 把源码编译成浏览器可执行的产物；vendor 指直接放在仓库里的第三方文件。
**本项目**：报告台用 **Vue 3 全局构建 + `web/vendor/`**，`index.html` 打开即用，**不需要 npm install**。

### 71. XSS 与 HTML 转义
**通俗**：把别人写的 `<script>` 当文字显示，而不是当代码执行。
**正式**：跨站脚本；对不可信内容做实体转义。
**本项目**：报告渲染器把 `<` `>` `&` 全部转义，所以文档里写 `<failure>` 不会变成标签。

### 72. 目录穿越之外：只监听 `127.0.0.1`
**通俗**：只允许本机访问，别人连不上。
**正式**：绑定回环地址而非 `0.0.0.0`。
**本项目**：报告台默认 `host="127.0.0.1"` —— 这是"工具"和"对外服务"的分界线。

## 七、本项目**没有**用到的热门名词（面试必须能正面回答）

> 原则：**没用不是不会，是当下不需要。** 每个都要能说清"它解决什么问题、什么条件下才该上"。

### LangChain —— 为什么没用
**它解决什么**：把"模型 + 提示词 + 工具 + 记忆 + 检索"串起来，省掉手写胶水代码；生态里有一堆现成集成。

**为什么本项目不需要**（三条判据，一条都没满足）：
1. **流程需要动态规划吗？** 不需要 —— 十步顺序是固定的。
2. **需要多角色协作吗？** 不需要 —— 三个受控调用点足够了。
3. **失败代价低、允许自由探索吗？** 恰恰相反 —— 测试工具一旦"自由发挥"就可能乱改测试。

**上了会怎样**：调试从"看一个断点"变成"看一段自然语言推理"，复现率从 100% 掉到"看运气"；而且多一层抽象，出了问题先怀疑框架还是自己，白折腾。

**什么时候该用**：要做"用户随便问、步骤不固定、需要调十几个外部 API"的对话式应用，且能接受不确定性。

**面试一句**：「框架解决的是"流程不确定"的问题。我的流程是确定的，上框架只会增加不确定性和调试成本。」

### 其余未用名词（一句话版）

| 名词 | 解决什么 | 为什么本项目不用 |
|---|---|---|
| **CrewAI / LangGraph** | 多 Agent 角色分工编排 | 一个流程只有"写"和"评"，没有多角色 |
| **向量数据库（Chroma / Milvus）** | 百万级向量检索与持久化 | 语料只有十余块，放内存即可；引入即运维成本 |
| **Rerank 模型** | 对候选结果二次精排 | 候选只有 3 条，没有精排空间 |
| **微服务 / Docker / K8s** | 拆分部署与弹性伸缩 | 单人本地工具，一条命令启动 |
| **Redis / 消息队列** | 缓存与异步解耦 | 没有并发与削峰需求（同时只跑一次） |
| **Playwright / Selenium** | 浏览器 UI 自动化 | 本工具测的是 HTTP 接口，不是页面 |
| **Langfuse / LangSmith** | LLM 调用链追踪与成本分析 | 只有 3 个调用点，日志足够；等调用点变多再说 |
| **ORM / 数据库** | 数据持久化 | 报告是文件，快照是文件，不需要库 |

## 八、速记卡（面试前 2 分钟过一遍）

**十步流水线**
`探 → 读 → 写 → 校验 → 评 → 快照 → 跑 → 分 → 定 → 报`

**六个数字**
- 4 道静态校验（语法 / 用例函数 / 接口白名单 / 返回成员白名单）
- 6 类失败 → 6 个动作
- ≤2 轮自愈（另有 1 次静态重试）
- 3 个受控模型调用点（生成 / 评分 / 兜底归因）
- 127 条离线测试
- 2 个真实被测项目（Python / Java）+ 1 个示例坏服务

**三句必背**
1. 「它测的不是 Python 也不是 Java，它测的是 HTTP —— 加一个项目就是加一个 json。」
2. 「自愈的第一条规则不是怎么修，而是**哪些不许修**：服务端 Bug 我绝不去改测试。」
3. 「AI 只用在它真正擅长的地方：写用例、判失败；规则能判定的一律不问模型。」

**三个必答**
- 为什么不用 LangChain / Agent 框架 → 第 7 节
- 为什么不用向量数据库 → 第 7 节
- 模型会不会靠改弱断言蒙混过关 → 「所以有 HOLD 和"缺陷不许修"，而且轮数上限只有 2」
