# REQ-001 · 门户与鉴权（cms-portal）

> 被测服务：桌面版 CMS（Spring 6 + Tomcat 11 + MyBatis-Plus + JSP）。
> 这份文档是"正确答案"，用来对照服务实际行为。

## FR-1 统一响应体

所有 `/api/**` 接口返回同一结构，字段名固定：

```
{ "code": 200, "msg": "操作成功", "data": ... , "success": true }
```

- 成功时 `code=200`
- 业务失败用 `code` 表达（400/401/403/404/500），**HTTP 状态码通常仍是 200**
- `msg` 必须是可直接展示给用户的中文提示

## FR-2 门户文章分页列表（公开，无需登录）

`GET /api/portal/list`，查询参数 `pageNum`（默认 1）、`pageSize`（默认 10）。

- `data` 必须同时包含 `total` / `pageNum` / `pageSize` / `pages` / `list`，否则前端算不出总页数
- `list` 为空时必须是 `[]`，不得为 `null`
- 每条元素至少含 `articleId`、`categoryId`、`title`
- 越界页码（如 `pageNum=9999`）应返回空列表 + 正确 `total`，**不得报 500**

## FR-3 门户文章详情（公开）

`GET /api/portal/article/{id}`

- 正常：`code=200`，`data` 含 `articleId`/`title`/`categoryName`
- 文章不存在：返回业务错误码，**不得 500**

## FR-4 文章评论列表（公开）

`GET /api/portal/comments?articleId={id}`

- `data` 必须是数组，元素含 `commentId`/`articleId`/`userName`
- 无评论时返回 `[]`
- 缺少 `articleId` 参数时应返回业务错误码，不得 500

## FR-5 图形验证码（公开）

`GET /api/auth/captcha` 返回 `image/png` 二进制（不是 JSON），并把验证码写入 Session。
登录接口 `POST /api/auth/login` 需要 `{username, password, captcha}`，因此**验证码与登录必须在同一个会话内**。

## FR-6 受保护接口必须拒绝未登录访问

除门户接口与验证码/登录/注册外，其余 `/api/**` 都要求登录态。未登录时：

```
{ "code": 401, "msg": "登录已过期，请重新登录", "data": null }
```

**注意**：拒绝方式是 **HTTP 200 + body.code=401**，所以只断言状态码是测不出来的，
必须断言响应体里的 `code`；并且 `data` 必须为 `null`，不得泄露任何业务数据。

## NFR-1 不泄露内部信息

任何失败响应都不得包含堆栈、SQL、内部类名等；只给出统一中文提示。
