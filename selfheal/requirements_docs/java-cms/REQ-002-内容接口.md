# REQ-002 · 内容接口（java-cms）

## FR-1 统一响应体

所有接口返回同一结构，字段名固定：

```
{ "code": 200, "msg": "操作成功", "data": ... }
```

- 成功时 `code=200`
- 业务失败用 `code` 表达（400/401/403/404/500），**不靠 HTTP 状态码区分**
- `msg` 必须是非空中文提示，可直接展示给用户

## FR-2 分类树

`GET /api/category/tree` 返回多级分类树，`data` 应为数组，每个节点含
`id`/`name`/`children`。空分类时应返回空数组，不得返回 `null`（前端要能直接遍历）。

## FR-3 文章分页

`GET /api/article/page` 的查询参数是 `pageNum`（默认 1）与 `pageSize`（默认 10），
**不是** `page`/`size`。可叠加 `title` 模糊查询、`categoryId`、`status` 过滤。

- `data` 必须同时包含当前页数据与总数，否则前端无法算出总页数
- 越界页码（如 `pageNum=9999`）应返回空列表 + 正确总数，不得报 500
- `pageSize` 必须为正整数；非法值不得导致服务异常

## FR-4 文章详情

`GET /api/article/{id}` 返回文章详情，并且浏览量 `viewCount` 加一。
逻辑删除的文章不得出现在详情与列表中。

## FR-5 写操作需要权限

新增/编辑/删除文章、审核文章都需要对应权限编码（`article:add` / `article:edit` /
`article:delete` / `article:audit`）。新增文章提交后进入**待审核**状态，不得直接发布。

## NFR-1 分页与总量一致

同一查询条件下，"总数"与"逐页翻到底拿到的条数"必须一致（这是分页实现最常见的错）。
