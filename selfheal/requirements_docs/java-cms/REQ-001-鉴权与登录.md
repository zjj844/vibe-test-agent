# REQ-001 · 鉴权与登录（java-cms）

> 这份文档是**被测项目（Java CMS）自己的需求**，不是测试工具的。
> 工具通过契约里的 `requirements_dir` 找到它，检索"该测什么"再写进提示词。

## FR-1 登录返回令牌

`POST /api/auth/login` 接收 `{username, password}`，成功后返回统一响应体：

```
{ "code": 200, "msg": "登录成功", "data": { "token": "...", "user": {...} } }
```

- `data.token` 必须非空，后续所有受保护接口都靠它
- `data.user` 必须包含用户基本信息与角色/权限编码
- 用户名或密码错误时不得返回 `code=200`

## FR-2 受保护接口必须校验令牌

除 `/api/auth/login` 与 `/api/auth/register` 外，所有 `/api/**` 接口都要求请求头：

```
Authorization: Bearer <token>
```

CORS 预检（OPTIONS）请求必须放行，不得要求令牌。

## FR-3 未登录必须被拒绝

令牌缺失、伪造、已过期时，接口**不得执行任何业务逻辑**，必须返回：

```
{ "code": 401, "msg": "未登录或登录已过期", "data": null }
```

注意：拦截器是直接写 JSON 响应的，**HTTP 状态码仍是 200**。
所以验证这件事只能看响应体里的 `code`，看状态码是看不出来的。

## FR-4 退出登录使令牌失效

`POST /api/auth/logout` 成功后，同一令牌再访问受保护接口应被拒绝（`code=401`）。

## NFR-1 拒绝信息不泄露内部细节

未登录时的响应不得包含堆栈、SQL、内部类名等信息，只给出统一文案。

## NFR-2 权限与身份分离

登录成功不等于有权限。`@RequirePermission` 标注的接口（如 `article:add`）在
令牌有效但权限不足时，应返回"无权限"（`code=403`），而不是 `401` ——
`401` 表示"你是谁不知道"，`403` 表示"知道你是谁，但你不能做这个"。
