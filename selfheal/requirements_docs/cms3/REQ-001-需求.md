SSM 企业级 CMS 验收需求（FR）· 按实际项目代码编写
依据：D:/dsh/cms-ssm-课程设计完整项目（cms-ssm 工程，Jetty 9.4.48，端口 8080，上下文 /cms）。
验收口径：每条 FR 均为可测试断言，「必须」「不得」为硬性要求；code 指统一返回体 {code, msg, data} 中的业务码（ResultCode：200/400/401/403/404/500），不是 HTTP 状态码；BusinessException 未显式带 code 时按 500 返回（BusinessException.java 单参构造）。文中 msg 均引用代码原文。全部条目通过方可交付。
FR-1 登录成功返回 token 与用户信息
POST /api/auth/login 成功时 code=200，data.token 为 32 位 UUID（无连字符），data.user 必须含 username / realName / phone / status / roles / createTime，不得包含 password；登录响应不得直接返回权限码集合，权限码仅经 GET /api/auth/info 返回。
FR-2 登录失败不得发 token
用户名不存在或密码错误时必须返回 code=500、msg=「用户名或密码错误」（UserServiceImpl#login），且 data 不得包含 token。
FR-3 禁用账号登录被拒
status=0 的账号登录必须返回 code=500、msg=「账号已被禁用，请联系管理员」，不得签发 token。
FR-4 注册默认 viewer
POST /api/auth/register 无需 token；username 必须 3–20 位、password 必须 6–20 位（RegisterDTO @Size，违反返回 400 及对应 message）；注册成功必须自动绑定 role_code=viewer，不得获得任何管理权限码。
FR-5 重复用户名注册被拒
用户名已存在时必须返回非 200、msg=「用户名已存在」（UserServiceImpl#register），不得产生第二个同名账号。
FR-6 token 有效期 7 天且过期自动清除
TokenManager 签发的 token 有效期必须为 7 天（EXPIRE_MILLIS）；过期 token 在下次校验时必须被移除并返回 code=401，不得继续放行。
FR-7 拦截范围与放行规则
拦截器必须覆盖 /api/**，且仅放行 /api/auth/login、/api/auth/register 与 OPTIONS 预检（spring-mvc.xml）；/api/auth/logout、/api/auth/info 与其余全部 /api 接口必须携带 Authorization: Bearer {token}，否则 code=401、msg=「未登录或登录已过期」，不得返回 500 或 200。
FR-8 退出即销毁 token
POST /api/auth/logout 后，原 token 再请求任意受保护接口必须立即返回 code=401，不得有效至自然过期（TokenManager#remove）。
FR-9 当前用户信息完整
GET /api/auth/info 必须返回 userId / username / realName / roles / perms 五个字段，perms 为该用户全部权限码列表；未登录时必须 code=401，不得返回 null 字段拼凑的响应。
FR-10 会话身份不得串号
AuthInterceptor#afterCompletion 必须清理 UserContext（ThreadLocal）；并发请求下后一个请求不得读到前一个请求的登录身份。
FR-11 密码不得明文
sys_user.password 必须存 SHA-256 加 8 位随机盐的 salt$hash（PasswordUtil），相同明文两次 encode 结果必须不同；任何接口响应不得出现密码字段。
FR-12 admin 全量放行
LoginUser.roles 含 admin 时，PermissionAspect 必须直接放行全部 @RequirePermission 校验，admin 必须可访问全部 18 个接口。
FR-13 缺权限码返回 403 且不进入业务方法
非 admin 用户权限码集合不含注解值时，必须返回 code=403、msg=「无权限访问该接口」，业务方法不得执行，并必须输出 warn 日志（含用户名、方法签名、缺失权限码）。
FR-14 editor 权限恰好 7 个码
editor 必须且仅绑定 category:add/edit/delete、article:add/edit/delete、log:page 共 7 个权限码（DataInitializer#editorPerms），不得包含 article:audit；editor 调用 PUT /api/article/{id}/audit 必须 code=403 且文章 status 不得变化。
FR-15 viewer 零管理权限
viewer 不得绑定任何管理权限码；viewer 调用用户管理、分类写操作、文章写操作、审核、日志接口必须全部 code=403。
FR-16 鉴权只由切面完成
18 个接口的权限校验必须全部由 PermissionAspect（@Around + @annotation）完成，Controller 与 Service 内不得出现权限码 if 判断；新增接口只加一行 @RequirePermission 即可生效。
FR-17 切面与 Controller 同容器
com.cms.aop 必须由 spring-mvc.xml 子容器扫描（与 controller、interceptor、exception 同容器）；父容器 spring-context.xml 必须排除 Controller/RestController 注解，同一类不得被两个容器各创建一份。
FR-18 统一返回体三段式
所有接口成功与异常路径必须都返回 {code, msg, data}；code 只允许 200/400/401/403/404/500（ResultCode），不得出现其它业务码。
FR-19 空集合必须为空数组
分页接口 data.records 为空时必须返回 []，不得为 null（PageResult.of 基于 Page.getRecords()）；分类树 children 为空时必须返回 []。
FR-20 参数校验失败返回 400 并提示首个字段
@Valid 校验失败必须返回 code=400 与第一个字段错误的 message（GlobalExceptionHandler#handleValidException），如「文章标题不能为空」「文章内容不能为空」「请选择文章分类」「分类名称不能为空」「审核状态不能为空」「请至少选择一个角色」，不得返回 500。
FR-21 业务异常按自带 code 返回
BusinessException 必须按其 code 原样返回；未显式传 code 时按 500 返回（如「文章不存在」「分类不存在」等单参构造调用点）。
FR-22 兜底异常不得暴露堆栈
未捕获异常必须返回 code=500、msg=「系统繁忙，请稍后重试」，响应体不得包含堆栈、SQL 或类名，服务端日志必须记录完整异常（log.error）。
FR-23 用户分页仅 admin
GET /api/user/page 需 user:page，editor/viewer 必须 code=403；keyword 必须同时模糊匹配 username 与 realName（OR），按 create_time 倒序，返回 records / total / current / size。
FR-24 用户状态只接受 0 和 1
PUT /api/user/{id}/status 的 status 为 0/1 之外的值必须返回非 200、msg=「状态参数不合法」；admin 不得禁用自己，msg=「不能操作当前登录账号」；目标用户不存在时 msg=「用户不存在」。
FR-25 禁用账号的边界行为（以代码为准）
被禁用账号再次登录必须被拒（FR-3）；其已签发的 token 在退出前仍然有效（拦截器不复查用户状态，AuthInterceptor 仅校验 token）——此为当前实现的真实行为，作为已知限制记录，修复后本条相应更新为「禁用后立即 401」。
FR-26 分配角色先清后绑且原子
PUT /api/user/{id}/role 必须先删除旧绑定再插入新绑定，整体处于 @Transactional(rollbackFor = Exception.class)，任一角色不存在（msg=「角色不存在：{roleId}」）时必须全部回滚；roleIds 为空必须 400「请至少选择一个角色」。
FR-27 分类树一次查库且有序
GET /api/category/tree 必须一次查全表后内存递归建树（CategoryServiceImpl#tree），不得按层级逐层查库；同级必须按 sort 升序、id 升序；仅登录即可访问，无需权限码。
FR-28 新增分类校验父分类存在
parentId > 0 时父分类必须存在，否则 msg=「父分类不存在」；缺省时 parentId=0、sort=0、status=1（CategoryDTO 默认值）。
FR-29 父分类不得设为自己
PUT /api/category/{id} 中 parentId 等于自身 id 必须返回非 200、msg=「父分类不能是自己」，不得形成自环、不得导致建树无限递归。（已知限制：当前不校验跨级环 A→B→A。）
FR-30 删除分类双重保护
DELETE /api/category/{id}：存在子分类时必须 msg=「该分类下存在子分类，无法删除」；存在文章时必须 msg=「该分类下存在文章，无法删除」（先查子分类后查文章，均用 selectCount）；两种情况均不得删除。
FR-31 分类不存在返回业务错误
update / delete 不存在的分类必须返回非 200、msg=「分类不存在」，不得出现 NPE 或 500 堆栈（BusinessException 兜底为 code=500）。
FR-32 分类写操作需对应权限码
POST /api/category、PUT /api/category/{id}、DELETE /api/category/{id} 分别需要 category:add / category:edit / category:delete，并必须写操作日志（@LogRecord module=分类管理）。
FR-33 文章多条件组合检索
GET /api/article/page 仅需登录；title（LIKE '%x%'）、categoryId（=0 时不生效）、status 任意组合必须同时满足全部已传条件，不得只按其中一个过滤；结果按 create_time 倒序，VO 必须含 category_name。
FR-34 列表页固定 2 条 SQL
列表查询必须固定为 COUNT + 数据共 2 条 SQL（ArticleMapper.pageList 第一参数 Page + LEFT JOIN cms_category）；不得出现 N+1（一页 10 条时不得出现 11 条 SQL）；Mapper XML 不得手写 LIMIT；分页插件必须注册 DbType.MYSQL。
FR-35 新增文章强制待审核
POST /api/article 必须忽略前端传入的任何状态：服务端强制 status=1、view_count=0、author=当前登录用户名（ArticleServiceImpl#add）；成功返回 msg=「提交成功，等待审核」；title / content 为空或 categoryId 缺失必须 400（对应 FR-20 的 message）。
FR-36 编辑文章限作者本人或 admin
非作者且非 admin 编辑文章必须 code=403、msg=「只能修改自己的文章」；编辑成功后 status 必须强制回退为 1（重新待审核），不得保留原状态；文章不存在时 msg=「文章不存在」。
FR-37 删除文章限作者本人或 admin 且为逻辑删除
非作者且非 admin 删除必须 code=403、msg=「只能删除自己的文章」；删除必须走 @TableLogic 逻辑删除（is_deleted=1），数据库行不得物理消失。
FR-38 已删文章全链路不可见
逻辑删除后的文章不得出现在 GET /api/article/page（XML 显式 is_deleted = 0），也不得通过 GET /api/article/{id} 查到（@Select 显式 is_deleted = 0），不得计入 total。
FR-39 详情返回 404 且浏览量自增
GET /api/article/{id} 对不存在或已删除的文章必须返回 code=404、msg=「文章不存在」（唯一使用 NOT_FOUND 的路径）；成功时 view_count 必须 +1 且采用最小更新（只写 id 与 viewCount），不得整行写回。
FR-40 审核仅 admin 且只接受 0/2/3
PUT /api/article/{id}/audit 需 article:audit；status 缺失必须 400「审核状态不能为空」；取值仅允许 0（驳回为草稿）/ 2（发布）/ 3（下架），其余必须 msg=「审核状态不合法，仅支持 0草稿 / 2发布 / 3下架」。
FR-41 审核最小更新
审核必须只写 id 与 status（ArticleServiceImpl#audit），不得整行写回，不得覆盖并发下他人修改的标题正文，不得误写 is_deleted；当前实现不校验文章当前状态（任意状态可被置为 0/2/3），此为真实行为，如实记录。
FR-42 分类删除保护与文章计数解耦
文章删除保护计数必须使用 articleMapper.selectCount（非查全列表）；分类删除前必须先查子分类数、再查文章数，两步独立，任一命中即拒绝。
FR-43 全局配置三件套
spring-context.xml 必须注册：逻辑删除全局配置（field=isDeleted，1/0）、分页插件（PaginationInnerInterceptor + MYSQL）、下划线转驼峰 mapUnderscoreToCamelCase=true；三者缺一对应功能即失效。
FR-44 时间字段自动填充
插入必须自动填充 create_time 与 update_time，更新必须自动填充 update_time（MetaObjectHandlerConfig），业务代码不得手写 set 时间，更新时 create_time 不得被改写。
FR-45 日志分页与过滤
GET /api/log/page 需 log:page；keyword 必须同时模糊匹配 username、module、operate_content（OR），按 operate_time 倒序，缺省分页 1/10。
FR-46 写操作必须自动留痕
所有标注 @LogRecord 的写操作必须由 LogAspect 落库，记录 userId / username / module / operateContent / operateMethod / operateIp / costTime / operateTime；业务抛异常时同样必须先记录再原样抛出（失败也留痕）；Controller / Service 内不得出现手工 save 日志。
FR-47 日志失败不影响主流程
日志写入异常必须仅输出 warn（记录操作日志失败），不得改变业务返回码、不得导致接口失败。
FR-48 接口总量与契约一致
系统必须且仅需提供 18 个接口：auth 4（register/login/logout/info）+ article 6（page/{id}/POST/PUT/DELETE/audit）+ category 4（tree/POST/PUT/DELETE）+ user 3（page/status/role）+ log 1（page），路径与方法必须与 docs/apifox-api.json 契约一致。
FR-49 启动即可演示
mvn jetty:run 后系统必须运行在 http://localhost:8080/cms（pom webApp contextPath=/cms，端口 8080）；sys_user 为空时 DataInitializer 自动写入：11 个权限码、3 个角色、3 个账号（admin/editor/viewer，密码均 123456）、6 个分类（Java技术→Spring框架/MyBatis、数据库→MySQL、前端开发，最大两层）、4 篇文章（3 篇已发布 status=2、1 篇待审核 status=1）；初始化必须只在父容器 ContextRefreshedEvent 执行一次，子容器事件必须跳过，重复启动（库非空）不得重复写入。
FR-50 编码与跨域
全局 UTF-8 编码过滤器必须生效（web.xml CharacterEncodingFilter，forceEncoding=true）；CORS 必须放行所有来源与 GET/POST/PUT/DELETE/OPTIONS（spring-mvc.xml mvc:cors）。
FR-51 Servlet 映射正确
DispatcherServlet url-pattern 必须为 /（不得为 /*），18 个 /api 接口必须全部可访问，静态资源 index.html 必须经 welcome-file 与 default-servlet-handler 正常返回，不得一律 404。
FR-52 验收用例全部通过
按本 FR 清单在 ApiFox 执行的用例（含每条权限码的正反例、每个状态迁移、每条删除保护、401/403/404/400/500 路径）必须全部通过，失败数为 0 方可交付。
